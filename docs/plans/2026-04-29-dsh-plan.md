# dsh 实现计划

> 基于 SPEC v0.1 | 2026-04-29

## 执行顺序

从最独立的底层模块开始，逐层向上。

---

## Phase 1: provider — DeepSeek API 接入

### 1.1 client.ts
- [ ] 实现 `DeepSeekClient` 类
- [ ] `chat()` 方法：非流式 HTTP POST 到 DeepSeek API
- [ ] `chatStream()` 方法：流式 SSE 解析
- [ ] 从 `DEEPSEEK_API_KEY` 环境变量读取 API key
- [ ] 错误处理：超时、4xx、5xx
- [ ] 类型定义：DeepSeekRequest / DeepSeekResponse
- [ ] 单元测试：mock HTTP，验证请求体和响应解析

### 1.2 router.ts
- [ ] 实现硬编码路由表 `ROUTES`
- [ ] `classify(command, taskType, fileCount)` 纯函数
- [ ] 返回 `{ model, thinking }` 
- [ ] 单元测试：覆盖所有路由场景

### 1.3 normalizer.ts
- [ ] `extractThinkingContent(response)` — 提取 `reasoning_content`
- [ ] `extractTextContent(response)` — 提取 `choices[0].message.content`
- [ ] `normalizeUsage(usage)` — 标准化 token 用量
- [ ] 单元测试

## Phase 3: core — 核心引擎

### 3.1 task-state.ts
- [ ] `TaskState` 类型定义（zod schema）
- [ ] `readTaskState(cwd)` — 读取 `.dsh/task-state.json`
- [ ] `writeTaskState(cwd, state)` — 写入
- [ ] `transition(state, newStatus)` — 状态机转换校验
- [ ] 单元测试：所有合法/非法状态转换

### 3.2 context-builder.ts
- [ ] `buildBaseContext(config)` — 规则文件内容 + 项目约束
- [ ] `buildRepoContext(cwd)` — 委托 repo/scanner
- [ ] `buildTaskContext(task, rankedFiles)` — 相关文件全文
- [ ] `buildDynamicContext(patches, verifyResults, maxRounds)` — 最近 N 轮
- [ ] `assembleContext(layers)` — 四层拼接，token 估算
- [ ] 单元测试

### 3.3 prompt-builder.ts
- [ ] `buildSystemPrompt()` — 固定 system prompt 模板（含协议 + 失败模式告警）
- [ ] `buildUserMessage(task, context)` — 拼接任务 + 分层上下文
- [ ] 单元测试：验证输出包含必需的 XML 块指令

### 3.4 patch-parser.ts
- [ ] `extractPatchBlock(response)` — 提取 `<PATCH>` 块
- [ ] `validateDiff(patch)` — 校验 unified diff 格式
- [ ] `parseHunks(patch)` — 解析 hunk header
- [ ] `applyPatch(cwd, patch, dryRun)` — 使用 `diff` 库 apply
- [ ] 单元测试：合法/非法 patch 格式

### 3.5 verifier.ts
- [ ] `runVerify(commands)` — 逐个执行 shell 命令
- [ ] `captureResult(command)` — stdout + stderr + exit code + 耗时
- [ ] `isAllPassed(results)` — 判断全部通过
- [ ] `formatResults(results)` — 终端格式化输出
- [ ] 单元测试：mock shell 执行

### 3.6 repair-loop.ts
- [ ] `runRepairLoop(state, client, maxRounds)` — 修复循环主逻辑
- [ ] 每轮：构建 DynamicContext → 调 DeepSeek → 解析 patch → apply → verify
- [ ] 循环终止条件：全部通过 或 达到 maxRounds
- [ ] 单元测试：mock client 返回

### 3.7 handoff-writer.ts
- [ ] `writeHandoff(state, format, outputDir)` — 生成交接文件
- [ ] Markdown 模板：修改内容、验证结果、修复历史、风险、下一步
- [ ] JSON 格式（`--format json`）
- [ ] 单元测试

## Phase 4: cli — 命令实现

### 4.1 main.ts
- [ ] CLI 注册（cac），6 个命令
- [ ] 全局选项：`--cwd`、`--config`
- [ ] `dsh --version` / `dsh --help`

### 4.2 init.ts
- [ ] 调用 repo/scanner 检测技术栈
- [ ] 调用 repo/rule-loader 提取规则文件
- [ ] 生成 `.dsh/config.yml`
- [ ] 生成初始 `.dsh/task-state.json`
- [ ] 终端输出

### 4.3 plan.ts
- [ ] 读 config + task-state
- [ ] 调用 file-ranker + context-builder
- [ ] 调用 router + client
- [ ] 调用 prompt-builder
- [ ] 解析 `<PLAN>` 块
- [ ] 写入 task-state，状态 → `planned`
- [ ] 终端输出计划摘要

### 4.4 patch.ts
- [ ] 确认状态为 `planned` 或 `repairing`
- [ ] 调用 client 生成 patch
- [ ] 调用 patch-parser 校验
- [ ] `--dry-run`: 只输出
- [ ] 默认：展示 + 确认
- [ ] `--auto`: 直接 apply
- [ ] 写入 task-state

### 4.5 verify.ts
- [ ] 读 config 获取验证命令
- [ ] 调用 verifier 执行
- [ ] 写入 task-state
- [ ] 终端输出结果

### 4.6 repair.ts
- [ ] 确认状态为 `verification_failed`
- [ ] 调用 repair-loop
- [ ] 终端输出每轮进度
- [ ] 达到上限后提示用户介入

### 4.7 handoff.ts
- [ ] 读 task-state
- [ ] 调用 handoff-writer
- [ ] 写入 `.dsh/handoff/`
- [ ] 终端输出摘要
